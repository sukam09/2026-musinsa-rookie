# 프롬프트 기록: 초기 기획 및 기술 스택 결정

## 1. 요구사항 분석 및 설계 요청

```
# Role
너는 복잡한 요구사항을 분석하여 최적의 기술 스택을 구성하고, 확장 가능한 아키텍처를 설계하는
**시니어 프론트엔드 개발자**야. 코드를 작성하기 전, 과제의 본질을 꿰뚫는 설계 청사진을 먼저 제안해줘.

# Task
첨부된 @PROBLEM.md 파일을 철저히 분석하고 다음 단계에 따라 설계 의견을 제시해줘.
**아직 실제 코드는 작성하지 마.**

## 1. 요구사항 분석 및 기능 로드맵
- `PROBLEM.md`에서 정의한 핵심 요구사항과 제약 사항을 요약해줘.
- 반드시 구현해야 할 **필수 기능**과 서비스 품질을 높일 수 있는 **심화 기능**을 구분해서 리스트업해줘.

## 2. 기술 스택 결정 (Tech Stack Selection)
- 이 과제를 해결하는 데 가장 적합한 기술 스택(Framework, State Management, Styling, Test 등)을 제안해줘.
- **"왜 이 기술인가?"**에 대해 다음 항목을 포함하여 논리적으로 설명해줘:
  - 과제 요구사항과의 적합성
  - 개발 생산성 및 유지보수 편의성
  - 성능 및 사용자 경험(UX) 측면의 이점
- 선택한 주요 라이브러리 간의 시너지 효과를 설명해줘.

## 3. 컴포넌트 설계 및 계층 구조
- 컴포넌트의 역할과 책임(SoC)을 분리하는 전략을 제안해줘.
- (예: Atomic Design, Headless 패턴, Compound Component 등 최적의 패턴 추천)
- 예상되는 컴포넌트 계층 구조(Component Tree)를 시각적으로 표현해줘.

## 4. 상태 관리 및 데이터 흐름 설계
- 전역 상태와 지역 상태의 범위를 정의하고, 데이터 흐름(Data Flow)을 어떻게 제어할지 설계해줘.
- 특히 파생 상태(Derived State)를 효율적으로 관리하여 '단일 진실 공급원(SSOT)'을 유지할 방법을 제시해줘.

## 5. 폴더 구조 및 확장성 설계
- 기술 스택과 설계 패턴이 반영된 최적의 `src/` 폴더 구조를 제안해줘.
- 각 폴더 및 파일 네이밍 규칙에 대한 가이드를 포함해줘.

## 6. 잠재적 리스크 및 해결 방안
- 구현 중 마주칠 수 있는 기술적 난제(성능 병목, 타입 복잡도, 브라우저 호환성 등)를 미리 예측하고 대안을 제시해줘.

# Output Format

- 가이드라인 준수를 위해 표(Table)와 구조화된 리스트를 적극 활용해줘.

## 12. README.md 보완 요청

```
# Role
너는 시니어 프론트엔드 엔지니어이자 기술 문서 작성 전문가야.
내가 진행한 프로젝트의 README.md를 논리적이고 전문적인 구조로 작성해줘.

# Task
제공하는 가이드라인에 따라 마크다운 형식으로 리드미를 작성해줘.
특히 '기술적 의사결정' 섹션에서 나의 설계 의도가 잘 드러나도록 '표(Table)'를 활용하는 것이 핵심이야.

# README 구조 및 순서
1. **프로젝트 소개 & 결과**: 프로젝트 명, 한 줄 요약, 그리고 실행 결과 스크린샷을 위한 플레이스홀더.
2. **구현 기능**: 사용자가 경험할 수 있는 핵심 기능 리스트.
3. **핵심 기술적 결정 사항 (Deep Dive)**:
   - 특정 방식(상태 관리, 컴포넌트 설계 등)을 선택한 이유와 근거.
   - [구분, 주요 내용, 기대 효과 / 참고] 컬럼을 포함한 분석 표 작성.
   - 필요 시 'AI 제안 vs 실제 적용' 비교 표 추가.
   - 각 결정 사항에 대한 Trade-off(장단점) 명시.
4. **기술 스택 (Tech Stack)**: 프레임워크, 라이브러리 및 상세 버전.
5. **프로젝트 구조 (Project Structure)**: 주요 디렉토리와 파일 구성 설명.
6. **실행 방법 (Getting Started)**: 의존성 설치 및 실행 커맨드 (코드 블록).

# 작성 가이드라인
- **엔지니어링 마인드**: 단순히 '무엇'을 만들었는지가 아니라 '왜(Why)' 그렇게 설계했는지를 증명하는 데 집중할 것.
- **가독성 최적화**: 표, 불렛 포인트, 코드 블록을 적절히 섞어 시각적으로 깔끔하게 작성할 것.
- **전문적 어조**: 간결하면서도 기술적 깊이가 느껴지는 문체를 사용할 것.

# 프로젝트 데이터 (여기에 본인의 내용을 채워주세요)

- 결정 사항 1: [예: Record<number, boolean>으로 상태 관리 - O(1) 접근 및 토글 로직 단순화]

- 결정 사항 3: [예: Smart/Dumb 컴포넌트 분리 - 관심사 분리 및 재사용성 확보]

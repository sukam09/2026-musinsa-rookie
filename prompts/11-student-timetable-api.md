# 프롬프트 기록

내 시간표 조회 API의 응답 스키마가 어떻게 될지를 먼저 보여줘.

옵션 B 스키마가 확장성 있는 구조인 것 같은데 이에 대해 좀더 자세히 설명해줘.

옵션 B로 확정하되, 배열의 형태로 되어 있는데 만약 item이 몇개 더 추가된다면 어떤 형태가 될지도 알려줘. 그리고 이 내용들을 [API.md](docs/API.md) [REQUIREMENTS.md](docs/REQUIREMENTS.md) 에도 추가해줘.

위 사항들 진행하고 나머지 의사결정에 대한 근거를 제시할 테니, 이것도 마찬가지로 [REQUIREMENTS.md](docs/REQUIREMENTS.md) 문서에 반영해줘.

- 정렬 기준은 시간표 순으로 할게. 추후에 UX를 고려했을 때 학생이 등록한 순서보다는 시간표 순대로 보이는게 더 자연스럽다고 생각해.
- 학생 미존재 처리 같은 경우는 학생이 존재하지 않을때는 404, 학생은 존재하나 등록한 시간표가 없을 때 빈 배열로 보여주는 것이 프론트엔드 입장에서 Response를 받을 때 판단하거나 예외 처리하기 더 좋을 것 같아.
